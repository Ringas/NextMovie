## 方法

安装 ARM64 包至 Android 11 ARM 转译模拟器。每个样本独立启动，严格使用所选站点的详情，禁止跨站兜底。验证首页、详情、播放解析、实际视频首帧、进度超过三秒和跳转后继续播放。

每站抽样一部内容的首条线路；不代表全部影片可用，也不是长播、HDR 或真实电视硬解验收。

## 立播诊断

同一模拟器网络、使用浏览器 UA 请求配置声明的 https://www.libvio.pw/，记录到 HTTP 403，响应正文长度39；未保存正文。这是该网络下该地址的观测，不推断所有网络均不可用，也不将其归因为播放器解码错误。未绕过访问限制、未关闭证书校验、未替换用户站点域名。

## 输入和记录

- 饭太硬、王二小使用此前下载的原始配置/JAR 快照，由本机临时服务分发，继续校验原 MD5；内容接口和媒体仍访问实际网络。快照成功不代表实时配置入口可用。
- 原始结果：artifacts/noncloud-20261124/results.json；HTTP 诊断：同目录 libvio-http.json。
- scripts/noncloud-smoke.py 支持 NONCLOUD_CASES 指定个别样本，QA_DIR 指定结果目录。
- 老探针在 seek 后再次收到渲染事件，因此全量记录将该时间命名为 lastFrameEventMs，不把它当作初始首帧延迟。探针 v2 已修正为只记第一次首帧，另抽样复测，结果位于同目录 timing/。

v2 的急救教学复测：已有首页快照8ms、详情3628ms（包含插件冷启动）、解析43ms、播放器首次渲染1333ms；跳转继续播放通过。这是单次样本，不用快照速度替代首次网络加载速度。测试结束已关闭本机临时配置服务器；模拟器保留实时 szyyds 配置，测试应用已停止。

本轮修改仅限 Debug 探针、测试脚本和记录，未修改生产播放逻辑或电视设置。ARM64 Debug 编译和 git diff --check 通过。
