# 设计规范（v0.1）

目标：10-foot UI，遥控器优先，影院暗场质感。**只借鉴方法论，不复用任何第三方素材、图标、品牌资产或源码。**

## 1. 色彩

| Token | 值 | 用途 |
|---|---|---|
| `Bg` | `#07080B` | 全局背景，接近纯黑但保留一点蓝调，避免电视发灰 |
| `Surface` | `#111318` | 卡片/输入框底 |
| `SurfaceHigh` | `#181B23` | 选中态、占位图 |
| `Accent` | `#E5C07B` | 焦点描边、主按钮、关键标签（香槟金） |
| `AccentDim` | `#66E5C07B` | 选中胶囊底 |
| `Text` | `#F4F5F7` | 主文本 |
| `TextDim` | `#9BA1AA` | 次要信息；对比度 ≥ 4.5:1 |
| `Stroke` | `#1FFFFFFF` | 未聚焦卡片描边 |

原则：**颜色只承担两件事**——指示焦点、区分层级。不做多彩渐变按钮。

## 2. 字体与层级

| 层级 | 字号 | 用途 |
|---|---|---|
| Display | 40sp | 首页/详情标题 |
| Headline | 28sp | 页面标题 |
| Title | 22sp | 分区标题 |
| Body | 16–18sp | 简介、列表项 |
| Label | 13–15sp | 角标、按钮、提示 |

沙发距离 2.5–3m，正文不低于 16sp；标题与背景之间必须有 scrim，禁止直接压图。

## 3. 布局栅格

- 屏幕内边距 48dp；
- 海报卡 132×198dp（2:3），间距 20dp；
- 首页结构：顶栏（56dp）→ 弹性留白 → Hero 信息（占宽 62%）→ 分区标题 → 海报行；
- 详情：海报 180×270dp + 28dp 间距 + 信息列（占宽 72%）；
- 一屏可见约 5–6 张海报，不追求密度，追求「一眼一张」。

## 4. 焦点与动效

| 行为 | 规则 |
|---|---|
| 聚焦 | 缩放 1.0 → 1.06，180ms `FastOutSlowInEasing` |
| 描边 | 1dp → 2dp，颜色 `Stroke` → `Accent` |
| 标题 | 未聚焦 `TextDim`，聚焦 `Text` |
| 背景 | 焦点变化时切换 Hero 背景图，200–300ms 交叉淡入（P1） |
| 禁止 | 视差、粒子、循环呼吸动画、超过 300ms 的转场 |

焦点恢复：从详情返回首页时恢复原海报位置（P1，用 `focusRestorer` + `LazyListState`）。

## 5. 图片策略：三级海报链路

顺序固定为 **L0 → TMDB（有 Token）→ L1（B站，无 Key）→ 源图**。任何一级失败都静默降级，绝不阻塞首屏。

### L0 源图 URL 尺寸升级（零请求，必做）

纯字符串改写，幂等，不改图源：

| 来源 | 列表尺寸 | 详情尺寸 |
|---|---|---|
| 豆瓣 | `s_ratio_poster` → `m_ratio_poster` | → `l_ratio_poster`；`view/photo/s|m/spic|mpic` → `l|spic` |
| 豆瓣域名 | `img[3-9]` / `qnmob*-sign` → `img1.doubanio.com` | 同左 |
| TMDB | `w185/w300/w342` → `w500` | → `w780` |
| B站 | 去掉 `@320w_200h.webp` 一类后缀，取原图 | 同左 |
| 百度 BCE | 去掉 `?x-bce-process=...` 缩放参数 | 同左 |

带防盗链的图由 `PosterImages.posterModel()` 统一补 Referer（豆瓣 `movie.douban.com`、B站 `www.bilibili.com`）。

**L0 已够清晰就停手**：命中 `/l_ratio_poster/`、`/m_ratio_poster/`、`/t/p/w500/` 等规则时直接使用源图，既保留源站更贴合的海报，也避免打第三方接口。

### L1 B站 PGC 兜底（无 Token 可用）

- 接口：`api.bilibili.com/x/web-interface/search/type?search_type=media_ft&keyword=`；
- 无 Key，返回 `title/org_title/pubtime/cover/eps[].cover/desc`；
- 严格校验：标题归一化后 ≥ 0.80（与 TMDB 同一套 `TitleMatcher`），年份不符直接拒；
- 频控：单进程串行 + 300ms 最小间隔 + 随机 `buvid3`（缺 cookie 会被 412）；命中 412/429 全局冷却 10 分钟；MISS 进 5 分钟负缓存；
- 调度：首页首屏 4 张、滚动再补 3 张，并发上限 2；详情页 1 次。

### 背景图与降级

1. TMDB `backdrop_path`（`w1280`）→ 2. 源站横版字段 → 3. B站 `eps[].cover`（16:9）→ 4. 竖版海报裁切 + 更重的渐变 scrim。
电影类 B站 返回通常没有 `eps`，因此无 Token 时第 4 档是常态；scrim 保证文字始终可读。

### 其他

- **模糊**：不在运行时做 `RenderEffect`（API 31+、低端盒子掉帧）；用渐变 scrim 代替；
- **内存**：Coil 按控件尺寸解码，滚动时取消在途请求；
- **占位**：`SurfaceHigh` 纯色 + 首字，不用随机骨架闪烁。

## 6. 性能预算（Amlogic 1–2GB 盒子）

| 指标 | 目标 |
|---|---|
| 冷启动到首页可交互 | < 2.5s |
| 常驻内存 | < 300MB |
| 首屏图片并发 | ≤ 2 路（含第三方兜底请求） |
| 单张海报解码 | ≤ 500×750 |
| 列表滚动帧率 | ≥ 50fps（1080p） |

超预算时的取舍顺序：先砍背景图分辨率，再砍动效，最后砍同时可见的列数。

## 7. 与 Marco 的关系

借鉴的是：暗场 + 海报墙 + 焦点放大 + 全屏背景 + 信息层级。
不借鉴的是：它的品牌资产（M 丝带标志）、截图、RGB 具体数值、XML/Java 布局实现。
视觉上通过「香槟金 + 更克制的动效」做区分，避免看起来像换皮。
